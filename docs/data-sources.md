# إضافة بيانات حقيقية — Data Sources Guide

المنصة تدعم أربعة مسارات لإضافة وتحديث البيانات، وكلها مبنية بالفعل:

## 1) استيراد GTFS (الأساسي للهيئات والجهات الرسمية) ✅ مضمّن

[GTFS](https://gtfs.org/) هو المعيار العالمي لبيانات النقل العام (نفس الصيغة التي تنشرها
جهات النقل في معظم دول العالم). أي ملف تحصل عليه من هيئة نقل أو وزارة أو مبادرة بيانات
مفتوحة يمكن استيراده مباشرة.

### من لوحة التحكم (الأسهل)
1. افتح لوحة التحكم → **استيراد GTFS**
2. ملف الـ feed يكون عادة `.zip` — فك ضغطه: `unzip cairo-feed.zip -d cairo-feed/`
3. اختر ملفات `.txt` من المجلد (المطلوبة: `stops.txt`, `routes.txt`, `trips.txt`, `stop_times.txt`
   — وملفات الأجور `fare_attributes.txt` / `fare_rules.txt` اختيارية)
4. اكتب اسم المصدر واضغط **استيراد الآن**

النتيجة: المحطات الجديدة تُنشأ، والمطابقة لاسم محطة موجودة تربط بدلًا من التكرار، والخطوط
تظهر فورًا في الموقع العام وفي محرك تخطيط الرحلات، ويُسجل كل شيء في **سجل التحديثات**
ومصدر البيانات. الاستيراد **تكراري** — أعد تشغيله عند تحديث الـ feed بدون خوف من التكرار.

### من سطر الأوامر (للأتمتة / cron)
```bash
cd apps/backend
DATABASE_URL="postgresql://…" DB_DRIVER=prisma \
  npm run import:gtfs -- --dir ./cairo-feed --source "GTFS هيئة النقل بالقاهرة" --url https://…
```

### ماذا يحدث داخل الاستيراد؟
| عنصر GTFS | التحويل |
| --- | --- |
| `stops.txt` | محطات — تُربط بالمدينة الأقرب (≤ 60 كم) وتُطابق بالاسم العربي لتفادي التكرار |
| `routes.txt` + `route_type` | وسيلة النقل (3=أتوبيس، 1=مترو، 2=قطار، 0=ترام…) |
| `trips.txt` + `stop_times.txt` | أطول تسلسل محطات للرحلات = مسار الخط، وأوقات التشغيل من أول/آخر رحلة |
| `fare_attributes/rules` | الأجرة (وإن غابت يستخدم المحرك أجرة افتراضية قابلة للتصحيح) |

**حدود مبسطة حاليًا** (قابلة للتطوير): تسلسل واحد لكل خط، لا تقويم رحلات `calendar.txt`،
والخطوط المستوردة تحصل على درجة موثوقية عالية مع مصدرها المسجل.

### أين تجد ملفات GTFS حقيقية لمصر؟
- **Mobility Database**: [database.mobilitydata.org](https://database.mobilitydata.org) — ابحث عن "Egypt"
  (تتوفر من حين لآخر خلاصات للقاهرة/الإسكندرية من مبادرات بيانات مفتوحة)
- المواقع الرسمية لوزارة النقل وهيئات النقل العام إذا نشرت ملفات مفتوحة
- مشاريع المجتمع على GitHub (ابحث: `egypt gtfs`)
- إن لم يتوفر ملف رسمي، يمكنك بناء ملف يدويًا بنفس الصيغة — انظر المثال الحي في
  [`apps/backend/sample-gtfs/`](../apps/backend/sample-gtfs) (٧ ملفات صغيرة تكفي)

## 2) الإضافة اليدوية عبر لوحة التحكم ✅ مضمّن

- **إضافة محطة**: لوحة التحكم → المحطات (إنشاء عبر الـ API: `POST /api/admin/stops`)
- **تعديل خط**: الأجرة، المواعيد، الحالة، درجة الموثوقية — مع تسجيل تلقائي في سجل التحديثات
- مناسب للبيانات الميدانية الصغيرة والتصحيحات السريعة

## 3) بلاغات المجتمع ✅ مضمّن

المستخدمون يرسلون بلاغات (أجرة خاطئة، خط متوقف، محطة في غير مكانها…) من الموقع العام،
وفريق الإدارة يراجعها من لوحة التحكم ويعتمد التصحيحات — هذا مصدر بيانات مستمر ذاتيًا.

## 4) OpenStreetMap (نموذج جاهز للتفعيل)

مخطط قاعدة البيانات يتضمن مصدر `OSM`، والجيوكودر يستخدم Nominatim بالفعل كملاذ أخير.
لاستيرام محطات/خطوط من OSM يمكن لاحقًا بناء محول يشبه مستورد GTFS يقرأ استعلامات
Overpass API ويحولها إلى نفس `ImportPayload` — البنية جاهزة لذلك.

### حزم البيانات الحقيقية المضمّنة في المستودع ✅ مضمّن
المستودع يضم نسختين من ملفات GTFS حقيقية لمصر داخل [`apps/backend/feeds/`](../apps/backend/feeds/)،
ويستوردها الخادم **تلقائيًا عند كل إقلاع** (`importBundledFeeds` — تكراري وآمن، لا يكرر البيانات):

| الحزمة | المحتوى | المصدر |
| --- | --- | --- |
| `portsaid-city-bus` | 13 خط أتوبيس/معدية حقيقي في بورسعيد، 678 محطة | [youssefelzedy/PortSaid-Transit-GTFS](https://github.com/youssefelzedy/PortSaid-Transit-GTFS) |
| `cairo-metro-2016` | مترو القاهرة: الخطوط 1 و2 و3، 189 محطة | [transportforcairo/Metro-GTFS](https://github.com/transportforcairo/Metro-GTFS) |

كل حزمة تحتوي ملف `meta.json` (اسم المصدر + أسماء عربية للخطوط) ومجلد `gtfs/` وملفات
`SOURCE.md` و`LICENSE.md` (الرخصة **CC BY-NC 4.0** — يُذكر المصدر في فوتر الموقع ويُحظر
الاستخدام التجاري). لإضافة حزمة جديدة: أنشئ مجلدًا بنفس البنية وستُستورد تلقائيًا.

### ملاحظة حول قاعدة الذاكرة (وضع التطوير)
الاستيراد اليدوي على المشغّل الافتراضي (الذاكرة) يضيع عند إعادة التشغيل، لكن **الحزم المضمّنة
تُستورد تلقائيًا عند كل إقلاع** فتبقى البيانات الحقيقية دائمًا متاحة. للبيانات الدائمة شغّل مع
PostgreSQL (`docker compose up`) وسيُحفظ كل استيراد نهائيًا.
